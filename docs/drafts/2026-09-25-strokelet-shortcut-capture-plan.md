# Strokelet 快捷键录制计划

**目标：** 设置窗口不再用固定按键下拉框。用户在录制框里按下自己的组合，窗口记下这次组合；之后手势注入的就是这些键。

**替换对象：** `settings/app.js` 里的主键下拉和修饰键开关，以及 `src/copy.rs` 里那份字母、数字、功能键、方向键名单。方向、触发键、直线判据、一次手势只注入一次，都不改。

**不在本计划内：** 自由形状、按应用区分、执行命令、按键序列（先 Ctrl+K 再按 C）、常驻监听键盘、开机自启。正式需求仍不承认设置界面；本计划确认前不得改 `docs/official/`。

## 用户怎么录

编辑一条规则时，快捷键是一个「按下快捷键」按钮，不再是名单。

点下去后出现录制状态，焦点留在设置窗口里。用户按下组合，例如 Ctrl+Shift+C。窗口显示刚按下的键。出现一个非修饰键后，这次录制结束。0 到 4 个修饰键加上这一个主键，和现在的和弦形状相同。左右修饰键分开记：按下的是右 Ctrl，注入时也是右 Ctrl。

录制只在这个状态里发生。下面任一情况立刻停止，并且不改已保存的规则：

- 用户按单独的 Escape，或点取消。带修饰键的 Escape 可以当成主键，例如 Ctrl+Escape。
- 5 秒内没有按下主键。
- 窗口失去焦点。
- 用户按下第二个非修饰键。这次作废，提示再录一次。
- 按键自动重复。重复事件丢掉，不把一个键记成很多次。

设置进程不打开 `/dev/input`，也不抓鼠标。演示进程继续只抓鼠标，不读键盘。

## 记下来的是什么

Linux 上 GTK 给出的键码比 evdev 键码大 8。录制时用 `键码 - 8` 得到要注入的 evdev 码。用一组已知键核对这个差：C 是 46，左 Ctrl 是 29，左 Shift 是 42。界面对用户显示键名，配置里同时留下这个码和显示名。注入只信码。

仍拒绝这些输入：

- 鼠标键、滚轮和游戏手柄键。
- SysRq、电源、睡眠、唤醒。这些键会触发机器级动作。
- 超过 4 个修饰键，或没有主键。
- 不是键盘键的码。

旧配置继续有效。`{"modifiers":["ctrl"],"key":"c"}` 仍表示左 Ctrl 加 C。新规则写成码，例如主键 46。名单外的合法键，比如空格、逗号、斜杠，可以保存。损坏文件仍然拒绝启动；重新加载失败时保留上一份规则。

## 注入

按下顺序不变：修饰键按 evdev 码从小到大按下，再按主键，再松开主键，再按相反顺序松开修饰键。每一步都有 SYN_REPORT。写到一半失败时，只松开本进程已经按下的键。

虚拟键盘在启动时声明全部键盘键，去掉上面拒绝的机器键和鼠标键。这样录到一个新键之后，不用拆掉虚拟键盘再重建。一次手势仍然最多注入一次。物理修饰键按住、扩展未就绪、会话锁定或暂停时不注入。

## 实施顺序

1. 让和弦接受 evdev 码，同时继续接受旧的键名。假键盘测试空格、逗号这种旧名单里没有的键，以及左右 Ctrl 不会被折成同一个键。
2. 拒绝鼠标键、SysRq、电源键、空组合和超过 4 个修饰键。旧的 `ctrl` + `c` 文件仍能读出左 Ctrl 和 C。
3. 虚拟键盘改为声明全部可注入的键盘键。补一个测试，确认拒绝名单里的码不在这张表里。
4. 设置窗口去掉主键下拉和修饰键开关。录制框只在打开时接收按键，Escape、超时和失焦都会停。保存的 JSON 带 evdev 码；正在运行的演示仍用现有 `reload` 重新读取。
5. 在编辑器里录一次 Ctrl+Shift+C，绑定到右键下划，确认注入的是这三个键。终端里的 Ctrl+C 仍会中断进程。

## 明确不做

- 不在演示进程里监听键盘，也不把录制做成全局钩子。
- 不记录录制框以外的按键。
- 不注入命令、文本或任意字节。
- 不支持两次按键组成的序列。
- 不因为这张新表去改直线识别阈值。
