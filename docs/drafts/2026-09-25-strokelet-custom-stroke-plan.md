# Strokelet 自定义轨迹计划

**目标：** 一条规则不再只能是上、下、左、右。用户按住触发键画出一条轨迹，松手后把它存下来；以后画出相近的轨迹，就注入这条规则上的快捷键。

**保留：** 同一个触发键、小幅点击仍重放该键、2.5 秒上限、最短约 80 counts、一次手势只注入一次。没有配置文件时，默认仍是右键直线向上 → Ctrl+C。快捷键录制方式不变。

**不在本计划内：** 多笔手势、按应用区分、旋转后仍算同一个字母、改轨迹颜色或线宽、执行命令。正式需求仍不承认设置界面；确认前不得改 `docs/official/`。

## 用户怎么录

编辑规则时，除了「按下快捷键」，再加「画出轨迹」。

点下去后，程序短时独占鼠标，不独占键盘。用户用当前选中的触发键按住并画出形状，松开后结束。窗口里用这条折线做预览。单独按 Esc、5 秒内没有按下触发键、或者画出的长度不够，都取消，不改已保存的规则。

如果演示进程正抓着鼠标，独占会失败。这时提示先在面板上暂停 Strokelet。暂停会放开鼠标。录完再取消暂停。设置窗口自己不长期抓鼠标。

## 怎么算对上

比较之前先把轨迹规范化，这样快慢和大小不影响结果：

1. 沿路径长度重采样成 32 个点。
2. 平移到重心。
3. 按较长的一边缩放到同一尺寸。
4. 不旋转。向上和向下必须是不同轨迹。

然后和每条已保存的轨迹比平均距离。最近的一条要明显近于第二名，并且距离小于固定阈值，才算命中。对不上任何一条就取消，不注入。

太近的两条不能同时保存。新轨迹如果会和已有轨迹判成同一个，就拒绝并提示再画一条更不同的。

规则最多 16 条。旧配置里的「方向」在读取时变成一条直线模板：上是从 `(0,0)` 到 `(0,-80)`，其他三个方向类推。所以现在的右键上划 Ctrl+C 不用重画。新保存的规则写点列，不再写方向。

点击判定不变：没超过 12 counts 仍是普通点击。超时、滚轮、额外键、丢帧仍然取消。原来那套「横向不能超过 30%」只用于生成内置直线；自定义轨迹改看上面的距离。

## 注入

命中哪条轨迹，就注入那条规则上已经录好的快捷键。顺序和失败时的松键方式不变。对不上就不按键。

## 实施顺序

1. 做纯比较函数。用假点列测试：平移和放大后的上划仍命中向上模板；下划不命中向上；弯钩不命中直线；两条太近的模板在保存时被拒绝。
2. 配置同时接受旧的方向规则和新的点列。缺文件时仍是右键向上 Ctrl+C。损坏文件拒绝启动。
3. 演示进程在松开时用点列选规则，不再只认四个方向。`reload` 后换上新轨迹，不重新抓设备。
4. 设置窗口加上画布预览和 `capture-stroke`。它只在录制时独占鼠标，失败时说明要先暂停。
5. 暂停演示，录一条和直线不同的轨迹并绑一个快捷键，取消暂停后在编辑器里画一次。终端里的 Ctrl+C 仍会中断进程。

## 明确不做

- 不把圆、折线自动认成字母。
- 不在演示进程里一直记录轨迹到文件。
- 不改 Shell 里那条实时轨迹的颜色和粗细。
- 不因为自定义轨迹放宽点击和超时。
