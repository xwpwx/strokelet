# Strokelet 手势与快捷键设置 GUI 计划

**目标：** 在现有右键直线手势和虚拟按键注入之上，加一个本机设置窗口。用户能添加、修改、删除「鼠标直线动作 → 一次模拟快捷键」。保存后，下一次手势按这张表注入，不再写死 Ctrl+C。

**不在本计划内：** 自由形状、录制轨迹、按应用区分、执行命令或脚本、终端专用逻辑、开机自启。首版正式需求仍只承认固定右键上划和 Ctrl+C；本计划确认前不得改 `docs/official/`。

## 用户能设置什么

一条规则是三元组：

| 字段 | 第一版允许的值 |
|---|---|
| 触发键 | 右键、中键、侧键前进、侧键后退。同一时刻只启用一个触发键 |
| 方向 | 上、下、左、右。同一触发键的每个方向最多一条 |
| 快捷键 | 0–4 个修饰键（Ctrl、Shift、Alt、Super）加一个主键，例如 Ctrl+C、Ctrl+Shift+C、Ctrl+V |

主键来自一份固定名单（字母、数字、功能键、方向键、Enter、Escape、Tab、Backspace、Delete）。不接受用户输入的命令字符串。

默认表只有一条：右键 + 上 → Ctrl+C。没有匹配规则的方向在松开时取消，不注入按键。触发键的小幅点击仍重放一次该键，让普通右击继续打开菜单。

识别继续用现在的直线判据：起步 12 counts、最短 80 counts、最长 2500 ms、横向不超过 `max(12, 净位移 × 0.30)`、直线度至少 0.85。四个方向共用这套数值，只是把「净上移」换成该方向上的净位移。counts 仍不是屏幕像素。

## 界面

用 GTK4 和 libadwaita 做一个独立窗口，由 `strokelet settings` 打开。它不抓鼠标，也不注入按键。

窗口里是规则列表，每行显示触发键、方向和快捷键。提供添加、编辑、删除。编辑用下拉选择触发键、方向和主键，修饰键用开关。保存前检查：快捷键非空、同一触发键没有重复方向、名单外的键不能保存。保存写入配置文件；若演示进程在听，再发一条只表示「重新读配置」的消息。

轨迹覆盖层和面板上的「划」保持现状。设置窗口不画在 Shell 扩展里。

## 配置与注入

配置路径：`$XDG_CONFIG_HOME/strokelet/gestures.json`，缺省时是 `~/.config/strokelet/gestures.json`。文件不可读、版本不对或某条规则非法时，演示进程拒绝启动并打印原因，不悄悄退回写死的 Ctrl+C。用户删除全部规则时可以启动，但任何方向都不注入。

注入顺序沿用现在的复制和弦：修饰键全部按下，主键按下，主键松开，修饰键按相反顺序松开，每一步都有 SYN_REPORT。写到一半失败时，只松开本进程已经按下的键。一次手势最多注入一次。物理修饰键仍被按住、扩展未就绪、会话锁定或暂停时不注入。

现有 Unix socket 只增加一种客户端消息：`reload`。它只让进程重新读取上面的配置文件。未知消息、命令字符串和任意按键名仍然拒绝。

## 实施顺序

1. 把「只认识上划并返回 Copy」改成「返回四个方向之一或 Cancel」。补上下左右、斜向、过短、超时的可回放测试。现有上划 80 counts 的用例改为向上方向命中。
2. 把固定 Ctrl+C 改成「按一份按键和弦注入」。用假键盘测试修饰键顺序、部分写入失败时的释放，以及名单外的键被拒绝。
3. 定义 JSON 配置的读写和校验。默认文件含右键上划 → Ctrl+C。损坏文件不能被当成空表悄悄启动。
4. 演示进程启动时读配置；收到 `reload` 后替换内存中的规则表，不重新抓取设备。匹配到方向才注入对应和弦。
5. 做设置窗口：列出、编辑、保存规则，并把 `reload` 发给正在运行的演示进程。窗口进程不打开 `/dev/input`。
6. 在编辑器里用自定义规则试一次，例如右键上划仍是 Ctrl+C，另加一条右键下划为 Ctrl+V。终端里的 Ctrl+C 仍会中断进程；这不是本计划要改的行为。

## 明确不做

- 不录制手势，不识别圆、折线和字母。
- 不按当前窗口或应用切换规则。
- 不执行 shell、脚本或任意命令。
- 不把用户加入 input 组，不安装 systemd 服务。
- 不在这一版里做阈值校准滑块。counts 和 2.5 秒上限先保持规格里的初值。
