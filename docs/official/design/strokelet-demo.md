# Strokelet 首版 Demo 架构

## 组件边界

- Rust 前台进程通过 evdev 读取用户明确指定的相对位移鼠标，经能力匹配的 uinput 虚拟鼠标透传正常事件，在 SYN_REPORT 边界识别手势。固定复制动作由受控虚拟键盘输出。
- GNOME Shell 扩展负责不响应指针事件的全局轨迹、暂停和状态显示。它在手势期间采样 Shell 实际屏幕指针位置，不用原始鼠标 counts 推算屏幕坐标。
- 双方通过本机 Unix socket 传递手势开始、结束、取消及桌面可用状态。协议需版本化、限制消息大小、校验对端身份；不得提供任意按键、命令或代码执行接口。
- Rust 侧可采用同步、有限超时的事件循环。具体 evdev、GJS 和 GNOME Shell 50 API 以实现时本机核实结果为准，Rust 依赖版本写入 Cargo.lock。

## 运行流程

1. 扩展建立连接并报告轨迹层可用；后台同时确认目标 logind 会话归属正确、处于活动且未锁定状态。
2. 确认物理按键全松开后，后台抓取所选设备，创建能力匹配的虚拟鼠标并开始透传。
3. 右键按下先暂存。指针位移继续透传，扩展收到 Begin 后采样真实屏幕指针；超过起步阈值才显示轨迹。
4. 松开时，小位移重放一次普通右击；有效上划在再次检查会话、连接、暂停及修饰键状态后发送一次 Ctrl+C；其他轨迹取消，不补发菜单。
5. End/Cancel 立即隐藏轨迹。断连、锁屏、会话失活、设备错误或退出时停止接管并释放本进程注入的按键。

## 权限与故障边界

- 仅输入进程获得所选设备和 uinput 所需权限；不以 root 运行 GUI 或任意用户命令，不把日常用户加入可读取所有输入的 input 组。
- socket 位于受限的 `/run/strokelet/<uid>/`，拒绝已有不明路径和符号链接；目录由 root 持有、组为目标用户主组、权限 0770，socket 由目标 UID 持有、权限 0600。目录不用 0750，因为目标用户需要在其中绑定 socket。使用 SO_PEERCRED 限制目标 UID；路径、所有者和权限均须在实现及测试中验证。
- 暂停时停止手势接管并隐藏轨迹，使普通右击仍由桌面处理；恢复前重新检查扩展和会话状态。
- 会话状态、修饰键状态或通信结果未知/超时时不注入 Ctrl+C；注入前再次检查。IPC 客户端不能直接请求 Copy。
- 启动先做短时限透传验证，退出时释放本进程持有的虚拟按键、关闭设备 FD 并清理自己的 socket；不得擅自释放物理键盘上的按键。
- 虚拟设备可能改变指针加速。需在目标鼠标上比较接管前后表现，不暗中修改用户全局鼠标设置。

安装包在用户登录、系统创建 `/run/user/<uid>` 时，以 root 只准备 `/run/strokelet/<uid>`：属主 root、组为该用户主组、权限 0770，并拒绝符号链接。用户服务自己不能提权，也不做这一步。服务进程仍是目标用户。uinput 用 udev `uaccess` 交给活动会话。`strokelet run --auto` 读取 logind 的图形会话；鼠标优先用 `~/.config/strokelet/device`，否则在唯一可用的相对鼠标或唯一的 `event-mouse` 路径上自动选择。

用户行为和验收见 [首版 Demo 需求](../requirements/strokelet-demo.md)；识别状态和阈值见 [手势识别规格](../specs/gesture-recognition.md)。
